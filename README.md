# langfix — תיקון שפת הקלדה בקיצור מקלדת

ממיר טקסט שהוקלד בפריסת המקלדת הלא נכונה: `akuo` ⇄ `שלום`.

**הקיצור: `⌘⌥;`** — Command + Option(⌥) + **המקש שמימין ל‑L**, זה שמדפיס `ף`
בעברית ו‑`;` באנגלית.

הקישור הוא ל‑keycode 41 ולא לתו `;`, ולכן זה **אותו מקש פיזי בשתי השפות**.
קישור לפי תו נשבר כאן: `hs.keycodes.map` משקף את הפריסה הפעילה, ובעברית התו
`;` יוצא ממקש אחר (keycode 50) — כלומר הקיצור היה זז למקש אחר לפי השפה
שהייתה פעילה כשHammerspoon עלה.

## איך זה בנוי

| שכבה | מה היא עושה |
|---|---|
| `langfix.py` (בתיקייה הזאת) | **המוח** — טבלת הפריסות, זיהוי הכיוון, החלטה מה לתקן. יש לו בדיקות יחידה |
| `~/.hammerspoon/init.lua` | **המקשים** — הקיצור הגלובלי, ⌘C/⌘V, החלפת שפת ההקלדה. חייב לחיות שם — זה נתיב קבוע של Hammerspoon |

הפייתון לא מדבר עם המקלדת בכלל בזרימה הזאת: Hammerspoon מעביר לו טקסט
בקובץ זמני (`--file`) ומקבל טקסט מתוקן. אפס ציטוט shell, ואפשר לבדוק את כל
הלוגיקה בלי מקשים ובלי הרשאות.

### למה Hammerspoon, ולא Quick Action

הגרסה הראשונה הייתה Quick Action עם קיצור בשירותים. היא עבדה — אבל
**באפליקציה אחת בכל פעם**: Quick Action רץ *בשם האפליקציה שהפעילה אותו*,
ולכן macOS דורש הרשאת נגישות מחדש בכל אפליקציה. גרוע מזה, באפליקציות
Electron התהליך האחראי הוא רנדרר־עזר שאין לו `.app` להוסיף לרשימה, ובשירותי
XPC (`WorkflowServiceRunner.xpc`) חלון ה‑`+` לא מציג אותם בכלל — כלומר אין
דרך לאשר ידנית.

Hammerspoon הוא תהליך אחד קבוע: **אישור אחד, בכל האפליקציות, לתמיד.**

## התקנה

```bash
brew install --cask hammerspoon
```

`~/.hammerspoon/init.lua` כבר במקום. מפעילים את Hammerspoon פעם אחת, ומאשרים
את בקשת הנגישות שקופצת — **הגדרות מערכת ← פרטיות ואבטחה ← נגישות ←
Hammerspoon**. הוא אפליקציה רגילה ב‑`/Applications`, ולכן מופיע שם כרגיל.

`hs.autoLaunch(true)` ב‑init.lua דואג שהוא יעלה בהתחברות.

לבדיקה שהכול חי:

```bash
hs -c 'return tostring(hs.accessibilityState())'   # צריך להחזיר true
```

### הגרסה הישנה

`~/Library/Services/Fix Keyboard Language.workflow` עוד קיים, אבל **בלי
קיצור** (השיוך הוסר כדי שלא יתנגש). הוא זמין מתפריט השירותים, ואפשר למחוק
אותו בלי לשבור כלום.

## שימוש

| מצב | מה קורה |
|---|---|
| יש טקסט מסומן | כל מה שסומן מומר — סימון הוא כוונה מפורשת |
| אין סימון | נבחר הטקסט עד תחילת השורה, ומתוקן ממנו **כל מה שהוקלד בשפה הלא נכונה** |
| לחיצה נוספת תוך 2.5 שניות | לא עושה כלום — הכיוון נעול, כדי שלא תהפוך בחזרה את מה שהרגע תוקן |

אחרי כל תיקון נשלח `Ctrl+Space` — שפת ההקלדה מתחלפת, אפשר להמשיך להקליד.

### מה נחשב "מה שהוקלד בשפה הלא נכונה"

המילה האחרונה, וכל מה שלפניה **באותה שפה** — עד המילה הראשונה שכבר בשפה
השנייה, שהיא הסימן שמשם הטקסט הוקלד נכון:

| לפני | אחרי | למה |
|---|---|---|
| `akuo yhkn` | `שלום טילמ` | כל השורה באותה שפה → הכול מומר |
| `שלום akuo` | `שלום שלום` | ה"שלום" הראשון הוקלד נכון → לא נגעו בו |
| `hello שלום` | `hello akuo` | אותו דבר בכיוון ההפוך |
| `akuo 123 yhkn` | `שלום 123 טילמ` | מספרים ופיסוק לא עוצרים את הריצה |

התיקון תמיד מוגבל ל**שורה האחרונה** — "מה שהרגע הקלדתי" לא חוצה שורה.

## בדיקה מהירה משורת הפקודה (בלי מקשים ובלי הרשאות)

מריצים מתוך תיקיית הפרויקט (`~/פרויקטים/תיקון טעות שפת הקלדה`):

```bash
echo "akuo" | python3 langfix.py --stdin      # → שלום
python3 langfix.py --text "שלום"              # → akuo
python3 langfix.py --fix "שלום akuo"          # → שלום שלום
python3 test_langfix.py                       # 20 בדיקות
```

`--text` ממיר את כל מה שנתת; `--fix` מריץ את אותה לוגיקה שרצה כשאין סימון.

## הגדרות

הקיצור, השהיות המקשים והשפות — בראש `~/.hammerspoon/init.lua`:

| קבוע | ברירת מחדל | מה זה |
|---|---|---|
| `MODS` / `KEY` | `⌘⌥` + `;` | הקיצור |
| `GUARD` | `2.5` | שניות שבהן לחיצה חוזרת לא עושה כלום |
| `MAX_LINES` | `3` | סימון גדול מזה נחשב פספוס של האסטרטגיה |
| `KEY_DELAY` | `12000` | מיקרו־שניות בין down ל‑up; להעלות בשדה איטי |
| `SOURCE_FOR` | ABC / Hebrew | לאיזו שפת הקלדה לעבור אחרי כל כיוון |

ההתנהגות של ההמרה — בראש `langfix.py`:

| קבוע | ברירת מחדל | מה זה |
|---|---|---|
| `DEBUG_LOG` | `True` | לוג ב‑`langfix.log`; רלוונטי רק למסלול ה‑Quick Action הישן |
| `SWITCH_INPUT_SOURCE`, `REPEAT_GUARD_SEC`, `CLIPBOARD_POLL_SEC` | | גם הם רק למסלול הישן — ב‑Hammerspoon כל אלה מטופלים ב‑Lua |

הפריסה עצמה היא `EN_TO_HE`; הטבלה ההפוכה נגזרת ממנה בקוד, אז מספיק לערוך
צד אחד. `test_langfix.py` מוודא שהמיפוי נשאר חד‑חד‑ערכי.

### אבחון

```bash
hs -c 'return tostring(hs.accessibilityState())'   # false = חסרה הרשאה
hs -c 'langfix()'                                  # להריץ בלי לחיצה
```

חלון הקונסולה של Hammerspoon (מהאייקון בשורת התפריטים) מציג שגיאות Lua.
`init.lua` נטען מחדש לבד בכל שמירה.

## מגבלות

- **רישיות** — בעברית אין אותיות גדולות, ולכן עברית→אנגלית מחזירה אותיות
  קטנות (`akuo`, לא `Akuo`).
- **הלוח** נשמר ומוחזר כטקסט בלבד; תמונה או קובץ שהיו בלוח יאבדו.
- **צריך ש‑Hammerspoon ירוץ.** אם הוא לא רץ, הקיצור פשוט לא קיים.
- **מצב "בלי סימון"** מנסה לסמן בכמה דרכים, הראשונה שמחזירה טקסט מנצחת:
  `⌥⇧↑` (עד תחילת הפסקה — חסין לכיוון, ולכן ראשון), אחריו `⌘⇧←`/`⌘⇧→`
  (עד תחילת השורה) ולבסוף `⌥⇧←`/`⌥⇧→` (מילה). כל אחד מהאופקיים מופיע
  בשני הכיוונים כי החיצים ב‑macOS זזים **ויזואלית**, וב‑RTL "אחורה" הוא
  ימינה. בשדה לא סטנדרטי שבו אף אחת לא תופסת — עדיף לסמן ידנית.
- ההדבקה מחליפה את כל מה שסומן, ולכן בעורך טקסט מעוצב (TextEdit במצב
  Rich Text) העיצוב בטווח הזה יישטח. בשדות טקסט רגילים אין מה לאבד.
- אם הטקסט שנבחר לא ניתן להמרה (רווחים, מספרים) — הסקריפט מבטל את הסימון
  ולא נוגע בכלום.

## הסרה

```bash
rm -rf "$HOME/פרויקטים/תיקון טעות שפת הקלדה" ~/.hammerspoon "$HOME/Library/Services/Fix Keyboard Language.workflow"
brew uninstall --cask hammerspoon
/System/Library/CoreServices/pbs -update
```
